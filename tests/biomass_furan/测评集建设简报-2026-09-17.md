# 检索测评集建设 · 进展与工期简报

**日期**：2026-09-17
**用途**：汇报进展、征询是否有更优方案

**一句话**：测评框架已建成、流程已跑通，**剩余标注约 1,221 条，按当前方式预计还需约 16 小时**。希望确认这个投入是否可接受，或是否有更经济的做法。

---

## 一、这件事在做什么

给**文献检索系统**做一套带标准答案的考卷，用来客观衡量"检索准不准"。

- 用户提问 → 系统返回最相关的文献片段 → 拿**标准答案**比对，判断对错
- 没有标准答案，就无法判断系统好坏，也无法比较改版前后的差异

**为什么费时**：标准答案（哪些片段能回答哪个问题）**不存在于任何现成数据里**，必须逐条判定。

## 七、若要压缩工期，可选方向

| 方向 | 预计效果 | 代价 |
|---|---|---|
| **A. 缩小首版题目范围** | 例如只做"固定测试 36 题"，时间省约 40%（≈ 6.4 小时） | 开发集与挑战集暂不完整 |
| **B. 降低等级粒度** | 只判"相关 / 不相关"二值，可省可观时间 | 失去 nDCG 分级能力，与业界惯例不一致 |
| **C. 改用 API 批量跑** | 并发可控，理论上更快 | 需控预算（**约 3,340 万 tokens 量级**）、需先做失败熔断 |
| **D. 减少题目数**（60 → 30） | 时间约减半 | 覆盖面下降，说服力减弱 |
| **E. 接受当前 16 小时** | 质量最完整、口径最规范 | 周期长 |

> **B / C / D 都会改变测评集口径或可比性**，必须记录版本，不能与现版本混用。
