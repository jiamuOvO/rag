# 相关性标注与复核指南

1. 先读完整问题，确定原料、目标产物、催化剂、溶剂、温度、时间、单位、研究来源和实验/预测属性。再读完整块，不能仅凭标题、关键词或检索分数判断。
2. 对每道题逐块判断全部冻结语料；跨页块以其实际文本为准，缺失表头或上下文时不得假定有完整实验事实。全文未提供的内容仍是未判断，不是0。
3. 3级：一块单独支持大部分或全部核心事实；2级：含必要直接证据但需要组合；1级：有背景帮助而不支持核心结论；0级：无法提供有效证据。无答案是假设，不是强制标签。
4. 正例保存 `evidence_quotes`、`reason`、`fact_ids`；引用须是当前块的连续原文，可仅规范化空白。证据不能从论文其他未出现在当前块的页面借用。
5. 区分yield、selectivity和conversion；wt%与mol%不能直接互换；理论预测与实验测量不能互换；果糖与葡萄糖、糠醛与HMF、单体与聚合物不可混用。
6. 0级必须经过语义检查并有判定理由；“没有搜到”“关键词未命中”“不是原始出题块”均不是足够理由。不要使用固定Top-K候选池替代全量判定。
7. 同一原文事实出现在多个实际块时各块分别标注，保留索引ID，不为了压低Recall分母而随意去重。同一论文的不同实验仍需检查条件。
8. 困难及多文档题逐事实检查证据组合；允许没有3级块，必须能覆盖全部必要事实。至少5个高相似干扰块是检查目标，实际不足时记录不足，不伪造干扰。
9. 独立第二轮检查所有非零标签、真实检索前5条及按题/来源分层抽取10%的0级。将等级分歧交由复审，不能由最后一次模型输出静默覆盖。
10. AI复核与人工复核分开记录。当前没有领域人员参与，不得填写人工姓名、虚构复核比例或Kappa。完整AI候选版仍不满足原始人工验收标准。

## 文件语义

- `seed_judgments.jsonl`：出题时核验的正例，不是完整qrels。
- `runtime/annotations.sqlite3`：可续跑逐对判断及批次记录；不修改生产数据库。
- `qrels.tsv`：只包含已判定组合。文件缺行表示UNJUDGED；不得让常规评测库默认把缺行作0而不披露。
- `annotation_records.jsonl.gz`：完整问题×块组合的状态账本；null明确表示尚未检查。
- `annotation_coverage.json`：覆盖率、待判定数量及复核状态。
- `annotation_conflicts.json` / `review_disagreements.json`：种子与模型、第一轮与复核的分歧；保留证据供裁决。
- `validation_report.json`：结构检查、语义覆盖、复核、泄漏、运行完成情况分别报告。结构通过不能替代语义通过。

## 命令

项目终端执行 `python -B tests/biomass_furan/annotate.py run --bridge http://127.0.0.1:8000`，通过测评模式服务完成第一轮全量判断。可用 `--max-batches 1` 验证首批；省略则续跑全部未完成批次。

第一轮完成后执行 `python -B tests/biomass_furan/annotate.py review --bridge http://127.0.0.1:8000`，然后执行 `python -B tests/biomass_furan/annotate.py export` 与 `python -B tests/biomass_furan/validate.py`。

没有本地服务时可使用 `--prompt-key` 直接隐藏输入Chat密钥。密钥只在进程内存中，不能写入任何数据集或日志。
