## 四、判定规范（v4，已冻结）

| 等级 | 含义 |
|---|---|
| 3 | 单独覆盖问题所需的**全部必需事实** + 硬性限定条件 |
| 2 | 直接支持**部分**必需事实，尚缺其他必需内容 |
| 1 | 对回答该题有**可说明的辅助价值**（须归入 5 类之一） |
| 0 | 与这题没有可说明的辅助关系 |

**1 级的 5 类辅助价值**：同体系不同条件 / 同原料不同体系 / 同论文方法与数据来源 / 直接相关机理背景 / 不同论文的同类对照

**第八节（v4 新增）· 题目明确指定来源时**：另一篇论文**独立陈述相同事实**只能判 **1 级**，不能判 2/3（阈值 ≥2，否则系统没找到指定文献也能命中）。
> `source_group` 字段可辅助定位，但**不能**当作所有题目的硬性过滤 —— 是否硬性**以问题措辞为准**。

**当前无正例的三道题**：`q_0012`（dev）、`q_0048`（test）、`q_0060`（challenge）—— 均为 `answerable=False` 且 `question_type=no_answer`，**属预设无答案题，零正例符合设计**。
> 但须记住：**「没有已知正例」≠「已证明全库无答案」**。

## 六、两个待决策问题

### 问题 A：0 级理由「按题给予」

**已澄清**：两批的 `judgment_encoding` 均为 `explicit_document_grade` → **等级是逐块给的**。0 级理由按题给一个是 **compact 格式的既有设计**（仅 2/3 级有逐条 proof）。
**影响**：无法从输出证明模型逐块看过。**需人工抽查**，不能因 JSON 合法就认定标签正确。

### 问题 B：输出 token 逼近上限（**优先级最高**）

q_0060 的 `completion_tokens = 3,921`，`max_tokens = 4,096` —— **余量仅 175**，但最终产出只有 5 条 87 字理由（≈125 tokens）。
**推断**：约 3,800 tokens 用于**思考过程** → 配置里的「关闭思考」**很可能在网关侧未生效**。这也解释了 q_0060 耗时 92 秒。

**风险**：思考更长即**顶到上限 → 输出截断 → 整批解析失败**。
**建议**：① 确认能否真正关闭思考；② 提高 `max_tokens`（推高费用）；③ 减小每批块数。
**在解决前不建议扩大执行。**
