# RAG 检索测评结果总结

- 日期：2026-09-18
- 项目：Li_Jia 科研论文 RAG v0.4.1
- 测评目录：`tests/biomass_furan`
- 数据集版本：`0.1.0-ai-candidate`
- 结果状态：`PROVISIONAL_UNJUDGED_AS_ZERO`

## 1. 执行摘要

本轮测评建立了一个面向生物质与呋喃研究文献的 60 题检索基准，用于比较生产 HTTP Hybrid 检索与隔离环境 BM25 检索。题目覆盖实验条件、数值、事实、机理、比较、跨文档、定义、改写、约束和无答案场景。

在当前 provisional qrels 下，HTTP Hybrid 的整体排序指标略高于 BM25：nDCG@10 为 0.5288、Recall@20 为 0.6954、MRR@10 为 0.7016；BM25 分别为 0.4893、0.6664、0.6736。Hybrid 对指定来源、英文问题和部分跨文档问题表现出更好的头部排序，但查询延迟更高，180 次正式请求中仅成功 149 次。BM25 的 180 次请求全部成功，P50 延迟约为 Hybrid 的三分之一。

这些结果不能作为正式验收结论。当前 frozen scope 覆盖率为 91.0%，仍有 118 个组合未判定；标签主要来自 AI 标注和 Agent 复核，未经领域专家完整验收。此外，HTTP 与 BM25 两次历史运行使用的 corpus hash 不同，因此两者差值不能全部归因于 Dense 检索。

## 2. 测评回答的问题

本测评主要回答：

1. 对给定科研问题，系统能否在前 1、3、5、10、20 名中召回直接支持问题的文本块？
2. 完整证据、部分证据、辅助证据与无关证据的排序是否合理？
3. Hybrid 检索相较纯 BM25 是否表现出潜在增益？
4. 检索服务在重复请求中的延迟和成功率如何？

本测评不直接回答：

- 最终生成答案是否正确、完整或无幻觉；
- 每一条自然语言结论是否被引用严格蕴含；
- 系统是否能在无答案时稳定拒答；
- 当前生产库全部 51 篇论文上的真实整体质量。

## 3. 题集与语料

### 3.1 题目结构

题集共有 60 题，其中中文 42 题、英文 18 题；57 题可回答，3 题预设无答案。

| 维度 | 分布 |
| --- | --- |
| 数据分区 | dev 12 / test 36 / challenge 12 |
| 难度 | easy 18 / medium 30 / hard 12 |
| 题型 | condition 9 / mechanism 9 / fact 9 / data 6 / definition 6 / comparison 6 / multi_document 6 / paraphrase 3 / no_answer 3 / constraint 3 |

每道可回答题包含问题、参考答案、必需事实、原文证据和指定来源。三道无答案题为 `q_0012`、`q_0048`、`q_0060`。

### 3.2 冻结语料与生产库差异

benchmark 快照包含 48 个来源和 5,066 个唯一文本块，其中 34 个来源状态为 `ready`、14 个为 `partial_failed`。

当前生产数据库则包含 51 篇论文和 5,444 个 chunks。生产库有 3 篇论文未进入 benchmark，共有 378 个数据库 chunk 不在冻结 `corpus.jsonl` 中。因此，本报告只描述冻结 benchmark 上的历史运行，不代表完整生产库。

## 4. 标注与计分口径

这里的“标注”是指：针对一个问题，预先判断每个候选文本块与问题有多相关。保存这些判断的文件称为 qrels（query relevance judgments，问题—证据相关性标注）。系统返回检索结果后，再把实际排名与 qrels 对照计算指标。

证据采用四级相关性：

| 等级 | 含义 |
| --- | --- |
| 3 | 单个文本块完整覆盖全部必需事实，并满足来源、体系和条件限制 |
| 2 | 直接支持部分必需事实 |
| 1 | 不直接支持必需事实，但具有可说明的辅助价值 |
| 0 | 无可说明的相关性 |

Recall、Precision、HitRate 和 MRR 将 grade ≥ 2 视为相关；nDCG 使用全部 0–3 等级。

frozen scope 共有 1,312 个唯一 `(query_id, doc_id)` 组合：

| 状态 | 数量 |
| --- | ---: |
| 已判定 | 1,194 |
| exhausted、未判定 | 118 |
| 覆盖率 | 91.0% |

已判定等级分布为 grade 0：663，grade 1：196，grade 2：200，grade 3：135。未判定组合没有被伪造为 grade 0；评分时仅以 provisional 方式按未判定为零处理，因此可能系统性压低指标。

## 5. 测评运行

每种方案执行 20 次 warmup 和 3 轮 × 60 题正式请求。质量指标固定使用 repeat 1，整体可靠性使用全部 180 次正式请求。

本报告比较的是两种检索方案：

| 名称 | 白话解释 | 实际组成 |
| --- | --- | --- |
| HTTP Hybrid | 通过真实 RAG 服务接口进行的混合检索 | BM25 关键词检索 + Dense 向量检索 + RRF 排名融合 |
| Isolated BM25 | 不启动完整服务，在隔离进程中只运行关键词检索 | 只有 BM25，不调用 Embedding，不执行 Dense 检索或 reranker |
| Hybrid - BM25 | 两次现有运行的指标差 | HTTP Hybrid 指标减去 Isolated BM25 指标；正数表示 Hybrid 较高，负数表示 BM25 较高 |

“HTTP”表示请求经过本地 Web API，因此包含网络传输、接口序列化和服务内部处理；“Isolated”表示直接在独立 Python 进程中调用检索逻辑。两者的延迟边界并不完全相同。

“Hybrid - BM25”当前只能理解为两次历史运行的表面差值，不能直接称为 Dense 向量检索的净提升。原因是两个 run 的 corpus hash 不同，即两次运行使用的语料快照并非完全一致。

### 5.1 HTTP Hybrid

- 模式：生产 HTTP 检索
- 检索：BM25 + Dense + RRF
- Top K：20
- 正式请求：180
- 成功：149
- 失败：31
- repeat 1：60/60 成功
- repeat 2：60/60 成功
- repeat 3：29/60 成功
- 31 次失败均位于 repeat 3

### 5.2 Isolated BM25

- 模式：隔离进程内检索
- 检索：BM25，Embedding 和 reranker 关闭
- Top K：20
- 正式请求：180
- 成功：180
- 降级标记：100%，原因为 `EMBEDDING_DISABLED`，符合该运行设计

### 6.2 可靠性与延迟

| 指标 | HTTP Hybrid | Isolated BM25 | 差值或比例 |
| --- | ---: | ---: | ---: |
| 正式请求成功率 | 82.8% | **100%** | -17.2 个百分点 |
| 查询延迟 P50 | 约 3.22 秒 | **约 0.92 秒** | Hybrid 约 3.5 倍 |
| 查询延迟 P95 | 约 3.54 秒 | **约 0.95 秒** | Hybrid 约 3.7 倍 |

Hybrid 的优势主要体现在相关证据的排序位置，而不是“是否在 Top 10 找到至少一个正例”。BM25 的 HitRate@20 略高，说明 Hybrid 并非在所有问题上都扩大了正例覆盖。

由于两个 run 的 corpus hash 不同，本表只能作为现状描述，不能作为严格的消融实验或 Dense 净增益证明。

## 8. 代表性案例

### 8.1 精确实验条件：两种方案都表现良好

问题 `q_0001`：

> 2019年SnCl4/EMIMBr研究比较金属盐催化剂时，木糖与离子液体各用了多少，催化剂与木糖的摩尔比是多少？

参考答案：木糖 200 mg、EMIMBr 1000 mg，催化剂与木糖摩尔比 1:10。

HTTP Hybrid 前 5 名均为 grade 3；BM25 前 6 名均为 grade 3。这类包含明确化学品、剂量和比例的题目具有较强字面锚点，两种检索都能稳定定位完整证据。

### 8.2 精确数值：完整证据均排第 2

问题 `q_0003`：

> 在2019年EMIMBr/SnCl4体系中，130℃下木聚糖反应半小时的糠醛收率和最高收率分别是多少？

参考答案：30 min 为 41.7%；1 h 达到最高 50.1%。

两种方案都将完整 grade 3 证据排在第 2 名，并在 Top 20 内召回全部 3 个已知正例。该题说明当前系统能够定位精确数据，但 Hybrid 对完整证据的头部排名没有形成额外提升。

### 8.3 指定来源：Hybrid 有明显头部排序改善

问题 `q_0013`：

> 2018年《Recent Trends in the Pretreatment of Lignocellulosic Biomass》综述列出木质纤维素的哪三种主要聚合物组分？

参考答案：纤维素、半纤维素和木质素。

该题要求证据来自指定综述。其他论文即使陈述相同事实但没有明确归因，也只能判为 grade 1。HTTP Hybrid 将指定来源的 grade 3 证据排在第 1；BM25 的前两名是其他论文中的 grade 1 辅助证据，指定来源的 grade 3 证据位于第 6。该案例表明 Hybrid 可能有助于处理来源限制，而纯关键词排名容易被“事实相同但来源不符”的文本占据头部。

### 8.4 跨论文机理：Hybrid 头部更完整

问题 `q_0057`：

> 比较2021年Pt1/Nb2O5-Ov制MF与2023年Pd-PdO/ZnSO4制糠醛两项研究：各自金属/氧化物位点如何分工，不能把哪项活化作用混同？

参考答案要求同时覆盖 Pt 活化 H2、Nb 活化 C—OH、PdO 层负责 Grob 裂解、Pd0 核促进最终脱水。

HTTP Hybrid 的第 1、2 名均为 grade 3；BM25 第 1 名为 grade 2，第一条 grade 3 位于第 3。这说明 Hybrid 在该跨文档问题上改善了头部完整性，但最终答案仍需要生成模型正确组合多个证据块，检索分数本身不能保证不混淆两套机理。

### 8.5 无答案：返回候选不等于可以回答

问题 `q_0060`：

> 知识库是否报道将2023年Al3+/黄腐酸葡萄糖光催化与2021年Pt1/Nb2O5-Ov氢化集成在同一连续装置，并给出连续运行1000小时的葡萄糖至MF总碳收率？

该题没有正例。两种检索仍返回候选，但其中没有已判定相关证据。这体现了 Top K 检索器的正常行为：总会返回相对接近的文本。系统是否据此正确拒答，需要另行评估生成答案和拒答策略，本检索测评不能给出结论。

## 9. 结果解读

可以形成的结论：

1. 当前检索已经具备可量化基线，不再只依靠个别演示问题判断效果。
2. Hybrid 在当前 provisional 口径下整体排序略优，尤其在指定来源和部分跨文档题上出现了有意义的头部改善。
3. BM25 的可靠性和延迟明显更好，并且在 HitRate@20 上没有落后。
4. 中文、机理和事实类问题是后续检索诊断的重点。
5. 无答案题证明系统可能召回表面相关文本，因此拒答必须由证据阈值和答案策略共同保证。

不能形成的结论：

1. 不能宣称 Hybrid 已被严格证明优于 BM25，因为两个历史运行的语料快照不同。
2. 不能把当前 qrels 称为完整人工金标或领域专家验收结果。
3. 不能由检索指标推断最终答案正确率、引用正确率或幻觉率。
4. 不能把本次结果外推到当前生产库新增的 3 篇论文和全部 5,444 chunks。
5. 不能把未判定的 118 个组合自动补成无关证据。

## 10. 后续建议

1. 从当前生产库导出新的冻结 corpus，并记录确定的内容哈希。
2. 在完全相同的 corpus、查询、frozen scope、qrels、Top K 和机器环境下重跑 BM25 与 Hybrid，形成严格可比基线。
3. 保留当前历史 run，不覆盖或改写原始结果。
4. 对 118 个 exhausted 组合继续保持未判定；若需要正式对外交付，引入领域专家抽检或复核。
5. 单独建立答案生成评测，覆盖必需事实、引用支持、拒答正确性、数值与单位保持以及跨文档事实混淆。
6. 优先分析中文、机理和事实类问题的召回路径，并区分查询分析、BM25、Dense、RRF 和证据过滤各阶段的责任。
7. 可靠性报告始终同时给出成功率、降级率和延迟分位数，不只报告成功请求的质量指标。

## 12. 术语表

### 12.1 系统与数据

| 术语 | 含义 |
| --- | --- |
| RAG | Retrieval-Augmented Generation，检索增强生成。先从知识库找证据，再让模型依据证据回答 |
| 检索 | 根据问题从知识库中寻找并排序相关文本，不等于生成最终答案 |
| Benchmark | 固定的测试题、语料、相关性标注和运行规则，用于重复比较系统表现 |
| Query | 一道检索问题；本项目使用 `query_id` 唯一标识 |
| Corpus | 参与测评的全部文本块集合，即冻结测评语料 |
| Source | 一篇来源论文或文献 |
| Chunk / doc_id | 从论文中切出的一个可检索文本块；benchmark 用 `doc_id` 标识，生产库中对应 chunk ID |
| Candidate | 检索或标注流程纳入考虑的候选文本块 |
| Evidence | 被用作问题支持材料的文本块；是否真正支持问题由相关性等级决定 |
| Frozen scope | 首版固定下来的“问题—候选文本块”组合清单；后续改判不能悄悄改变清单范围 |
| qrels | Query relevance judgments，人工或 Agent 给出的“某文本块对某问题有多相关”的标准答案 |
| Corpus hash | 对整个语料快照计算的数字指纹；hash 不同通常意味着语料内容或排列不同 |

### 12.2 检索方法

| 术语 | 含义 |
| --- | --- |
| BM25 | 关键词检索算法。词语越匹配、越具有区分度，排名通常越高 |
| Embedding | 把问题或文本转换成数字向量，用于比较语义相似度 |
| Dense 检索 | 使用 Embedding 向量相似度找语义相近文本，即使双方没有使用完全相同的词也可能匹配 |
| Hybrid 检索 | 同时使用关键词检索和向量检索，再合并两边的排名 |
| RRF | Reciprocal Rank Fusion，倒数排名融合。根据候选在多个检索列表中的名次合成最终排名 |
| Reranker | 对初步召回的候选再次排序的模块；本次两个正式 run 都没有启用独立 reranker |
| Top K | 只观察排名最前面的 K 条结果，例如 Top 10 就是前 10 条 |

### 12.3 质量指标

| 指标 | 白话解释 | 关注点 |
| --- | --- | --- |
| Recall@K | 全部已知相关证据中，有多少被找进前 K 名 | 是否漏掉相关证据 |
| Precision@K | 前 K 名结果中，有多少是真正相关的 | 返回结果是否干净 |
| Hit Rate@K | 每道题的前 K 名里是否至少出现一个相关证据，再对全部题取平均 | 能否至少找到一条可用证据 |
| MRR@10 | 第一条相关证据排名倒数的平均值，只查看前 10 名；越靠前分数越高 | 首个可用证据出现得多早 |
| nDCG@K | 同时考虑相关性等级和排列位置；完整证据排在前面得分最高 | 整个前 K 排序是否合理 |

这些指标都在 0 到 1 之间，越高通常越好，但侧重点不同。例如，系统可能 Hit Rate 很高——大多数问题至少找到一条证据——同时 Recall 较低，因为仍漏掉了很多其他相关证据。

### 12.4 运行与统计

| 术语 | 含义 |
| --- | --- |
| Run | 按固定配置完成的一次完整测评运行 |
| Warmup | 正式计时前的预热请求，用于减少首次加载和缓存冷启动的影响 |
| Repeat | 对同一批题重复运行；本项目每种方案正式运行 3 轮 |
| Repeat 1 | 第一轮正式结果；本报告固定用它计算质量，避免事后选择表现最好的一轮 |
| HTTP | 通过 Web API 请求真实服务，包含接口和传输开销 |
| Isolated | 在独立进程内直接运行检索逻辑，不经过 HTTP 服务 |
| P50 | 延迟中位数；一半请求比它快，一半比它慢 |
| P95 | 95% 请求能在该时间内完成，常用于观察慢请求体验 |
| Degraded / 降级 | 某个组件不可用时使用较弱但可运行的替代路径，例如关闭 Embedding 后仅运行 BM25 |
| Provisional | 临时、非最终。表示标注尚不完整或验收条件尚未全部满足 |
| Unjudged | 尚未获得有效相关性等级的“问题—文本块”组合，不等同于无关 |

本报告是对当前可验证产物的总结，不替代原始数据、标注规范或后续领域专家验收。
