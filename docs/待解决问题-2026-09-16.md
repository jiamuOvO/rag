# 待解决问题台账

更新时间：2026-09-16。本文记录已观察到的问题与验证方向；除明确标为“已修复”的事项外，不应把记录视为已经实施的改动。

## P1：证据列表与答案内实际引用不一致

**现象**：一次回答的页面列出 8 篇候选文献，但答案正文只实际使用了其中 2 个引用编号。用户无法区分“被模型用于结论的证据”与“仅被检索到、但未引用的候选”。

**影响**：证据可追溯性被削弱，且可能让读者误以为全部 8 篇都支持答案结论。

**期望**：默认只展示答案内实际出现的 citation；如需保留其余候选，单列为“检索候选，未用于结论”，并不得与正式引用混排。

**验证方向**：以答案文本中的 `[ev_*]` / `[n]` 为准计算实际引用集，检查 API 响应、前端列表与正文引用集一致；补充“候选多于实际引用”的回归测试。

## P1：引用侧栏中的 PDF 表格布局失真

**现象**：右侧引用预览中，PDF 表格内容未按二维表格展示，数值被逐行竖排。截图中可见 `Run times` 下的 `0、10、20…` 与其他列分离，阅读上下文丢失。

**影响**：用户难以正确理解表格数值、列名及对应关系；若以其作为证据，可能造成误读。

**可能原因**：PDF 文本层提取为阅读顺序文本，而不是保留表格坐标/单元格结构；当前引用预览直接展示抽取文本。

**验证方向**：选取该 Eucalyptus sawdust / Fig. 4 页面作为固定回归样本，比较原 PDF 渲染、PyMuPDF block/word 坐标和引用侧栏输出。确定采用表格重建、图片/原 PDF 局部预览，或明确标记为“表格文本可能失真”后再实现。

## P0：已存在的精确证据未被召回，导致答案错误

**现象**：问题“木聚糖在 30 分钟时的糠醛收率是多少，最高收率又是多少？”被回答为“知识库未直接报道”。

**已核验证据**：`2019_furfural_from_biomass_SnCl4_PMC6384620.pdf` p.10–11 的 `chk_a31155b8bf9d90dce8836014` 与 `chk_8cc5cec9a375be2393d7efb8` 明确记载：EMIMBr/SnCl4、130°C 下，30 min 为 **41.7%**，1 h 最高为 **50.1%**。

**影响**：系统以“缺少证据”拒答已被知识库精确覆盖的问题，并用不相干的戊糖/半纤维素数据替代。

**验证方向**：将该问句及更具体的条件问句加入端到端检索回归；记录 BM25、Dense、RRF 各腿的候选与排名，定位是查询分析、召回深度、融合还是生成阶段丢失了金标 chunk。修复不得以放宽金标断言或将不相干证据伪装成支持为代价。

## P2：页级检索过滤在大库上的查询成本

**现象**：`scoped_chunks()` 为保证跨页安全性，对每个候选 chunk 执行 `NOT EXISTS` 与 `COUNT(*)` 两个相关页范围子查询。查询计划命中 `idx_pages_paper(paper_id,page_number)`，不是整页表扫描，但仍是随候选 chunk 数近似线性增长的索引查找。

**当前基线**：5,066 个官方可检索 chunks 时，单次 `scoped_chunks()` 实测约 77–84 ms；完整 `/v1/retrieve` 约 2.9 s，当前主耗时仍在 Dense 查询。Dense 双路可能重复范围筛选。

**决定**：暂不优化。达到任一条件后立项：`scoped_chunks()` p95 超过 200 ms、官方可检索 chunks 超过 50,000，或全库新版切块后超过约 100 篇中等长度 PDF。

**后续方案**：在 `chunks` 物化 `retrievable` 标记；入库、OCR 质量修复或页面状态变化时同步更新覆盖该页的 chunks。查询改为索引化的 `c.retrievable=1`，原页范围 SQL 留作回填与一致性校验。必须保留“跨页 chunk 覆盖任一异常页即排除”的约束。
