# PDF 文本层污染与局部 OCR（2026-09-15）

## 现象与原因

部分数字生成 PDF 在阅读器中显示正常，但 PyMuPDF 提取出的文本包含 `U+0001`、`U+0002`、`U+0003` 等控制字符。例如页面显示 `potential`，文本层为 `poten<U+0002>al`。

PDF 阅读器绘制字体 glyph；文本提取依赖字体的 glyph-to-Unicode / `ToUnicode` 回译表。该表缺失或错误时，视觉内容可以正常，复制、搜索和 RAG 提取文本却会错误。PyMuPDF 官方 issue #530 和 #4716 记录了同类问题。修改字体 `ToUnicode` stream 可以修复已知字体，但需要逐字体确定映射，不适合作为通用入库策略。

## 与常见 RAG 流程的比较

本项目的“原生文本层优先，文本过少时 OCR，再切片、Embedding 和索引”与 PyMuPDF、pypdf 和 Unstructured 的建议一致。PyMuPDF 指出 OCR 远慢于普通文本提取，应先判断是否需要；Unstructured 的 `auto` 策略在 PDF 文本可提取时使用 `fast` 原生提取，不可提取时才使用 `ocr_only`。

原实现对任何控制字符都尝试整页 OCR。双栏论文的整页 OCR 虽然置信度达到 0.957–0.982，却只保留原文本层 27%–56% 的词量，因此被 60% 质量门拒绝。这避免了静默丢失正文，但整页 OCR 成本高，而且少量坏 glyph 会让整页和整篇标记为 `partial_failed`。

## 局部 OCR 策略

当前实现逐个检查 PyMuPDF text block，只渲染含异常字符的 block。替换必须同时满足：

1. OCR 置信度不低于 0.85；
2. OCR 不再含控制/私用区/替换字符；
3. OCR 词量不少于原 block 的 60%；
4. 清理标点后的字符序列相似度不低于 0.55；
5. 异常字符位于两个英文字母之间，属于可验证的断裂单词。

第 5 条是科学正确性边界。公式中的控制 glyph 可能代表负号、乘号、箭头或括号；即使 OCR 输出看起来干净，也不能自动推断其语义。公式 block 继续保留原文本并标记人工复核。

成功替换的页面使用 `ocr_local_quality_recovery`，其余正文不变。一个页面仍有未恢复控制字符时继续标记 `partial_failed`，不会伪装成完全成功。

## 三篇样本的结果

- `2022_impact_of_hydronium_ions_on_the_pd.pdf`：局部 OCR 可恢复 `potential`、`relative`、`concentration`、`hydrogenation`、`adsorption` 等普通词；公式 glyph 保留警告。
- `2023_scalable_electrosynthesis_of_commodity_chemicals_from_biomass.pdf`：异常均位于公式，保留原文和警告。
- `2023_the_role_of_oxygen_vacancy_in_bifunctional.pdf`：异常均涉及反应式或公式运算符，保留原文和警告。

局部 OCR 的目标是减少明确可修复的正文污染，不是让所有论文强行变成 `ready`。获得正确 `ToUnicode` 的出版社/作者版本仍是公式文本的首选修复。
